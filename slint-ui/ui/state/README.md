# 界面状态

`../state.slint` 只负责导出 Rust 绑定，没有统一的 `AppState` 或兼容转发层。Slint 业务组件从以下模块直接导入需要的状态；Rust 控制器通过 `app.global::<PlayerState>()` 等具体类型访问。纯展示组件继续接收属性与回调。

| 模块 | 所有权与操作 |
| --- | --- |
| `runtime.slint` | 运行模式、运行提示、后端命令与封面请求接口 |
| `navigation.slint` | 当前窗口的路由与可用尺寸 |
| `account.slint` | 登录状态、用户身份 |
| `login.slint` | 登录表单、验证码、二维码、翻转动画与登录生命周期 |
| `settings.slint` | 通用、外观、缓存设置，以及设置窗口导航 |
| `audio.slint` | 音质、设备、软件音量、BitPerfect、会话音量锁与可调节条件 |
| `player.slint` | 当前歌曲、进度、播放状态与播放控制 |
| `queue.slint` | 待播列表与控制器入口；排序、去重、下一曲及保存仍由 Rust 执行 |
| `player_view.slint` | 播放器浮层、全屏配色、歌词与评论展示 |
| `playlist.slint` | 歌单详情、所有权、侧栏歌单与编辑生命周期 |
| `detail.slint` | 搜索、专辑、喜欢歌曲共用的活动结果视图 |
| `library.slint` | 本地音乐列表与移除/清空回调 |
| `home.slint` | 首页推荐、专辑、榜单及各自加载状态 |
| `search.slint` | 搜索输入、分类和结果展示状态 |
| `artist.slint` | 歌手资料、发行作品和热门歌曲 |
| `dialog.slint` | 确认对话框内容与待确认目标，关闭后清理目标 |
| `song_menu.slint` | 歌曲菜单定位和添加到歌单的明确目标 |
| `download.slint` | 下载目标和可用音质 |

`../fixtures/` 按首页、曲库、播放器、歌单、歌手保存只读演示数据。业务模型以这些数据初始化；运行时仍由控制器加载和更新。歌单曲目不再绑定到活动详情结果，切换搜索或专辑结果不会替换独立歌单的数据。

跨业务联动通过少量明确的单向依赖完成：歌单编辑器观察账号和路由；播放器浮层观察音频可用性，评论请求读取当前歌曲；登录操作更新账号。账号、路由、音频状态不反向依赖这些界面。确认对话框集中拥有待确认的删除目标，视图将确认动作交给对应控制器。

每个顶层窗口有自己的全局对象。`src/windows.rs` 分别订阅 `SettingsState.settings-changed`、`AudioState.audio-changed`、`RuntimeState.runtime-changed`，只同步发生变化的设置或提示。路由、窗口尺寸、登录表单、弹窗、设置标签页、歌曲与播放队列不会因此跨窗口复制。主题继续使用独立的主题通知。

结构检查对每个全局对象限制为 120 个有效代码行、80 个声明成员、5 层嵌套，并检查导入循环。新增功能应先确定所属业务模块，不能向导出入口添加属性，也不能通过压行绕过限制。状态边界和跨窗口行为由 `src/state_tests.rs`、`src/window_tests.rs` 及原有登录、歌单、播放回归测试覆盖。
