# 歌曲列表操作审查（2026-11-10）

审查范围为 Slint 与 Electron 的歌曲列表、播放队列、当前歌曲、收藏及歌单增删调用链。重点检查重复保存的顺序和选中状态、组件直接修改列表、业务操作散落在事件分支，以及操作目标依赖弹窗的临时状态。

| 发现 | 处理 |
| --- | --- |
| 在播放队列以外维护 `next_ids` / `nextSongIds`，需要额外同步删除、选曲、清空和恢复 | 删除额外顺序。添加下一曲只在原队列中插入或移动；按已选播放模式继续选曲 |
| Slint 队列增删、替换、选曲、前后切换散落在 `View` | `runtime/queue.rs::PlaybackQueue` 私有化顺序和当前 ID，提供统一方法；真实运行时和演示适配器共同使用 |
| Slint 待播清单、本地清空弹窗和首页推荐直接改写列表 | 组件只调用动作；演示操作归入 `playlists.rs` / `playlists/queue.rs`，清空后的播放器显示共用 `playback_ui.rs` |
| Slint 收藏、歌单增删和本地单曲移除位于通用事件分支内 | 提取为 `runtime/view/song_actions.rs` 中独立方法，保留登录、所有权、本地歌曲及重复请求限制 |
| Slint 添加到歌单通过全局菜单状态猜测歌曲，播放器弹窗没有固定目标 ID | 显式传入歌曲 ID；播放器打开弹窗时保存目标，后续切歌不改变该操作对象；缺少参数不执行操作 |
| Electron 播放与队列 store 各自保存当前歌曲 ID，依赖监听同步 | ID 由队列 store 保存，播放 store 通过计算属性读写同一状态，持久化也只有一个入口 |
| Electron 待播清单直接 `splice`、本地音乐直接筛选播放数组、音频模块直接替换歌曲元数据 | 统一调用 `removeFromPlaylist`、`removeSongs`、`updateSong`；拖动排序通过 `setPlaylist` 提交，播放器公开只读列表类型 |
| Electron 清空列表与停止播放在多个界面拼接 | `clearAndStop` 统一处理，待播清单和退出登录复用 |

本地曲库、云端歌单、当前页面和播放队列具有不同含义，保留各自的数据源；Slint 的行模型是供界面显示的投影。它们不是额外维护的“下一曲优先列表”。已有 `runtime/library.rs` 和 Electron 曲库/歌单 store 的文件与远程写入方法继续负责持久化。

新增检查规则 `model-mutation` 拒绝 Slint 组件对上述歌曲模型及其行字段直接赋值；忽略注释、字符串和只读比较。Rust 的队列字段保持私有，不暴露可修改的切片。

回归覆盖直接插入/去重/移动、当前曲目保护、空队列、播放模式、播放/暂停/加载状态与进度、实际保存退出恢复、队列替换删除清空、滚动复用行的正确目标、登录与未登录菜单、收藏请求保护及演示入口。Electron 测试覆盖同一份当前 ID 的同步读写和保存恢复，以及列表操作方法。

验证结果：`cargo test --locked` 80 项通过、14 项需要特定桌面/网络/手工环境的测试默认跳过；`cargo build --locked` 成功；`npm run test:web` 16 个文件、159 项通过；`npm run typecheck` 通过。Slint 质量检查 58 个文件、0 个问题，检查器的 13 项回归测试通过。没有执行真实声卡播放和桌面拖动测试。
