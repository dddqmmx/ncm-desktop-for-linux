# 主页布局与内容

保留 Electron 首页 20px/24px 页面内边距、32px 页面标题、22px 分区标题、40px 分区间距、200×250 歌单卡与 176px 专辑封面。新碟直接复用 AlbumItem，榜单沿用中性半透明底色、18px 圆角和现有文字颜色。底部保留 120px，最后一排能滚到播放器上方。

新增内容来自独立的公开接口，不重复侧栏歌单或搜索分类：

- `album_newest`：新发行专辑封面、名称、歌手，点击打开专辑详情。
- `toplist_detail`：最多六个带歌曲摘要榜单的封面、名称、更新说明和前三首歌曲，点击打开完整榜单。前三首摘要没有歌曲 ID，因此不提供误导性的单曲播放按钮。

两个分区进入视口后分别请求，独立显示加载、空状态、错误及重试。失败不影响推荐和播放状态；切换账号时隔离旧响应，并恢复被取消的加载。新碟最多 24 张、榜单最多 6 个，内容与封面保持按可见范围创建。

2026-11-09 按新的交互要求调整：推荐歌单、推荐歌曲和新碟列表统一使用 `DragShelf`，按住鼠标左右拖动浏览，保留左右按钮。主页本身关闭鼠标上下拖动，垂直滚轮用于上下滚动；此限制仅适用于主页。横向列表不再用滚轮翻动；卡片上的垂直滚轮交给主页上下滚动，纯横向滚轮不会改变列表位置。使用 Flickable 的方向判断、拖动阈值、惯性和点击取消，拖动卡片不会打开歌单、进入专辑或播放歌曲。卡片外仍保留 12px 的悬停与阴影空间。

首页模型共用逐行追踪的 `CoverModel`，单张封面到达只通知对应卡片，不再使整排文字、布局失效。列表进出视口的状态只在布尔值实际改变时提交，避免每个纵向滚动像素都使卡片池重新绑定。横向卡片池保留视口外的一张复用卡片，通过可见性控制绘制，跨边界时不反复销毁卡片；整组移出页面视口后仍释放控件。自动回归验证单张封面只读取对应项、纵向滚动不会重新读取整排卡片，以及拖动、滚轮传递、点击、长列表和模型缩短。

同日在完整运行时使用已保存账号和真实 API 验证：首页横向拖动输入处理的中位数 / P95 为 0.67 / 0.84ms（Vulkan、Wayland、debug、100 次输入）。检查拖动未触发打开或播放，卡片上的垂直滚轮使整页移动。此数值只衡量输入处理，不是整帧渲染时间；在线复测入口见 `tests/playlist-performance.md`。

2026-11-09 修复首页回滚时图片反复解码：此前所有卡片请求 800px，榜单的 256px 请求也被向上归入 800px。64 MiB 解码缓存只能保留约 26 张 800px 方图，翻页时挤掉旧图并把对应模型的封面清空，回滚又要从磁盘读取、解码并上传纹理。

首页现在按实际物理像素请求封面，计入屏幕缩放和专辑封面的 1.06 倍悬停放大；下载及缓存命中统一使用 128 / 256 / 384 / 512 / 800 / 1600 档位。150% 缩放时两类卡片使用 384px，200% 时歌单卡使用 512px、专辑使用 384px。64 MiB 预算、按需创建控件及全屏 1600px 高清请求保留，已加载图片随模型保存在缓存中，重建卡片不需要重新解码。长期浏览超过预算仍会正常 LRU 淘汰。
